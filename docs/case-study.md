# 真实案例：30 FPS 的真相

> 一次完整的排查记录。症状看起来像"画质问题"，实际上是**机器被人拿去挖矿了**。

---

## 1. 症状

| 项目 | 情况 |
| :--- | :--- |
| 机器 | 联想拯救者 Legion 5 Pro 16ACH6H（82JQ） |
| CPU / GPU | Ryzen 7 5800H / RTX 3070 Laptop 8GB（默认 TGP 115W，最大 140W） |
| 内存 / 屏幕 | 16GB（2×8GB DDR4-3200 双通道）/ 2560×1600 165Hz |
| 硬盘 | 两块 1TB **无 DRAM** NVMe（WD Green SN350 / 长城 GW300） |
| 游戏 | 《三角洲行动》WeGame 版 |
| 设置 | 2560×1600，**画质全部最低**，超分开到内部渲染仅 **1484×928（58%）** |
| 帧数 | **30 - 50**，且"特别卡" |

**用户的自述判断**："好像是缓存的问题。"

---

## 2. 第一个矛盾点

按常理，RTX 3070 Laptop 在 928p + 最低画质下应该跑 **120 帧以上**。

于是先做了一件事：**采样。

| 指标 | 实测 |
| :--- | :--- |
| GPU 占用 | 平均 **36.5%**，最高 48% |
| GPU 功耗 | 平均 79W（上限 115/140W） |
| GPU 频率 | 1765MHz（正常，没降频） |
| GPU 温度 | 73°C（正常） |
| **CPU 占用** | **89.1%** |
| 可用内存 | **401MB**（提交 25.3GB） |

**结论**：100% 的采样点里 GPU 占用都 **< 50%**。显卡有 2.5 倍余量。

> 这直接推翻了"画质 / 缓存"的假设 —— 降画质一帧都不会多。

---

## 3. 转折：游戏关了，CPU 还是 80%

关掉游戏后再测：

- 系统 CPU：**78% ~ 85%**
- 可用内存：**95 ~ 165MB**

一台只在待机的电脑不可能这样。**有东西在偷跑。**

但普通权限下 `Get-Process` 只能看到 11 个进程，性能计数器 `\Process(*)` 的实例列表同样被过滤 —— **看不到元凶**。

于是改用 `\Processor Information(_Total)` 和 `\Process(_Total)` 做差值估算：**约 8 个核心的 CPU 消耗没有归属**。

---

## 4. 提权后，真相浮现

用带 UAC 提权的 PowerShell 重新枚举进程，拿到了完整列表：

| 进程 | CPU | 路径 |
| :--- | ---: | :--- |
| **`Nu6aAeJC`** | **696%**（约 7 核） | `C:\ProgramData\H5nfMjC1\Nu6aAeJC.exe` |
| `EsURYVtn` | 20% | `C:\ProgramData\EsURYVtn.exe` |
| `OvQZGLSc` | 20% | `C:\ProgramData\cjP6h231\OvQZGLSc.exe` |

**随机 8 位小写名字 + ProgramData 路径 + 父进程是 `svchost`** = 典型的计划任务启动的挖矿木马。

更狠的是：停掉其他服务后 CPU 只从 89.6% 掉到 87.1%，因为**矿机会立刻把空出来的核心吃掉**。

---

## 5. 完整入侵链

| 组件 | 位置 | 作用 |
| :--- | :--- | :--- |
| 3 份伪装程序 | `Users\Public\{随机5位名}` | 冒充"腾讯/阿里安全组件" |
| 2 份伪装程序 | `Program Files (x86)\{随机5位名}` | 伪造版本信息，冒充 Edge 更新任务 |
| **CPU 矿机** | `ProgramData\{随机8位}\...exe` | 696% CPU |
| 加载器 / 守护 | `ProgramData\{随机8位}\...exe` | 相互拉起 |
| **反向隧道后门** | `ProgramData\Microsoft\System\System.exe` | 伪装成 "Cloudflare Modernization Service"，连陌生域名 |
| **9 个恶意计划任务** | 各种伪装名字（`Task Workflow Infrastructure`、`Risk Capacity Execution`、`MicrosoftEdgeUpdateTaskUA ...`） | 重启后自动复活 |
| **Defender 被废** | `DisableAntiSpyware=1` + 服务 ACL 篡改 | 4 个月无防护 |

**同一台机器上还有两个用户自己装的"共享赚钱"客户端**：

- 共享 **GPU 算力**（把闲置显卡租出去跑 AI 任务）
- 共享 **CPU / 带宽 / 硬盘**（做 CDN 节点）

这两个合法软件会和游戏抢资源，是"卡顿"的次要原因。

---

## 6. 处置与结果

处置顺序（每一步都用数字验证）：

```
停共享类服务      → CPU 89.6% → 87.1%   （只降 2.5%，没打中，继续查）
提权枚举进程      → 发现 Nu6aAeJC 696%
杀进程 + 隔离文件  → CPU 86.8% → 15.9%   （命中）
查持久化          → 发现 9 个恶意计划任务
删任务 + 复查      → 未复活
```

| 指标 | 处置前 | 处置后 |
| :--- | ---: | ---: |
| 空载 CPU | 86.8% | **15.9%** |
| 可用内存 | 324MB | **3,736MB** |
| C 盘剩余 | 36.9GB | **97.8GB** |
| 游戏帧数 | 30-50 | **90-150** |

---

## 7. 这个案例教给我们什么

1. **"帧数低"先别调画质** —— 先看 GPU 占用。GPU 没吃满，瓶颈就在别处。
2. **空载 CPU 是第一诊断指标** —— 它异常高的时候，问题与游戏设置无关。
3. **普通权限看不全进程** —— 需要提权才能看到 `svchost` 拉起的木马。
4. **"处理一步就测一次"** —— 停错服务时 CPU 只降了 2.5%，这个"幅度不够"才是继续挖下去的关键线索。
5. **杀毒软件被关本身就是入侵痕迹** —— 不是"优化"，是有人动过。
6. **合法的"赚钱"软件也会拖垮游戏** —— 共享算力/带宽类客户端在打游戏时必须退出。

---

## 8. 后续建议

- **立刻改密码**：Steam / 微信 / QQ / 邮箱 / 网银（有反向隧道 + 潜伏 4 个月）
- **修好杀软**：Defender 的 ACL 被改后很难修复，建议重装系统或换用干净杀软并全盘扫描
- **观察一周**：定期跑 `scripts/03_security-audit.ps1`，确认木马没有复活
- **加内存到 32GB**：16GB 跑 Win11 + 常驻软件 + 三角洲确实紧张
